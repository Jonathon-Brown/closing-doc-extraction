# closing-doc-extraction

A LoRA fine-tune of **Qwen3-8B (4-bit)** that pulls a fixed JSON schema out of Florida real estate closing documents (deeds, mortgages, closing disclosures, title commitments, HOA disclosures). It runs fully on a MacBook with MLX.

**Adapter:** [huggingface.co/jonathonbrown/closing-doc-extraction-qwen3-8b-lora](https://huggingface.co/jonathonbrown/closing-doc-extraction-qwen3-8b-lora) · **Full results and caveats:** [RESULTS.md](RESULTS.md)

## Why

Title and closing teams retype the same 16 fields from every document. These files are confidential, so sending them to a cloud API is often off the table. The goal is a small local model that gets the structure right every time without a long prompt.

## Results (held-out test set, n = 30)

| | Base + full schema in prompt | Fine-tuned, no schema in prompt |
| --- | --- | --- |
| Valid JSON | 100% | 100% |
| Schema conformance | 66.7% | **100%** |
| Field accuracy | 90.0% | **100%** |
| Field accuracy on 10 real, out-of-distribution forms | n/a | 96.3% |

**Read this before trusting the 100%:** 292 of the 302 documents are synthetic, generated by `qwen3:32b` from templates, and the labels came from the same model. In practice this is **distillation of a 32B model's extraction behavior into an 8B adapter.** The test set comes from the same distribution, so it measures template matching. The 10 real CFPB and FAR/BAR forms are the honest out-of-distribution check. [RESULTS.md](RESULTS.md) breaks this down field by field.

**Findings worth knowing:**

- Most of the gain is in grantor/grantee vs. borrower/lender roles. That convention isn't visible from the key names, so a prompt alone can't teach it.
- Adding the schema prompt back to the fine-tuned model *lowers* accuracy (100% to 95.2%), because the adapter was trained without a system message.
- On real forms, a 2048-token cap truncated one dense closing disclosure. 4096 fixed it.

## Pipeline

```
templates ──qwen3:32b──> 302 docs ──qwen3:32b (format: json, temp 0)──> labels
   │                                                      │ schema-validated
   └──────── stratified 80/10/10 split (seeded) ──────────┘
                     │
        mlx-lm LoRA (rank 8, alpha 20, top 16 layers, lr 1e-5, 600 iters)
                     │
               eval.py: 4 configs × valid-JSON / schema / per-field accuracy
```

## Reproduce

Needs an Apple Silicon Mac and [Ollama](https://ollama.com) with `qwen3:32b` pulled (the teacher). Everything is written under `./work/`, which is gitignored.

```bash
pip install -r requirements.txt
cd pipeline
python build_fl_corpus.py   # 292 synthetic Orange County docs + 10 public CFPB / Florida Realtors PDFs
python extract.py           # PDF/DOCX -> work/finetune/docs.jsonl
python generate.py          # teacher labels via Ollama, schema validation, seeded 80/10/10 split
python regen_fix.py         # relabel deeds + mortgages with the party-role rule (see below)
python regen_fix2.py        # relabel closing disclosures + title commitments, add consistency checks
cd ..
mlx_lm.lora --config lora_config.yaml                                     # ~600 iterations
python eval.py --model mlx-community/Qwen3-8B-4bit --adapter-path adapters/          # fine-tuned
python eval.py --model mlx-community/Qwen3-8B-4bit --system-prompt SCHEMA            # baseline
```

`samples/examples.jsonl` holds five held-out test examples (a deed, a mortgage, a closing disclosure, a title commitment, and an HOA disclosure) so you can see the exact input and target format without running anything.

### Why there are two "regen" scripts

My first labeling prompt (`generate.py`) never told the teacher how to assign party roles, so deed and mortgage labels mixed up grantor/grantee and borrower/lender. Rather than relabel everything, `regen_fix.py` re-runs only deeds and mortgages with an explicit content-based role rule. `regen_fix2.py` does the same for closing disclosures and title commitments, and adds a per-category check that each category produces one consistent `document_type`. Both rebuild the splits with the same seed, so train and test never mix. I kept the scripts as they were run, because they are the actual history of the dataset.

One step isn't scripted: the 10-document out-of-distribution file used in RESULTS.md was cut by hand from the labeled `real-forms` category.

## What I'd do next

1. Hand-label 50 real documents so there's a ground truth that doesn't come from the teacher model.
2. Add the teacher (`qwen3:32b`) and constrained JSON decoding as baselines, to show what the fine-tune buys over grammar-forced output.
3. Test on OCR'd scans, not clean PDF text.
